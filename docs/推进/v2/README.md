# v2 推进目录

这个目录用于集中管理所有与 `v2` 有关的文档。

## 当前定位

`v2` 不再把重点放在“继续补强单终端页面”，而是转向“结构化 AI 工作台”。

当前明确的核心对象是：

- `TaskCard`：工作项与人工推进单元
- `DocCard`：结构化文档、阶段说明、交接说明和关键节点记录
- `Session`：真实运行中的 shell / agent 上下文

当前明确的主要视图是：

- `CanvasWorkspace`：主工作面，用于整体理解、布局、观察和调度
- `ListWorkspace`：监控和筛选面，用于快速发现需要响应的任务和 session

## 当前原则

- `CanvasWorkspace` 的首要职责是帮助开发者一目了然地观察和调度，不默认作为 session 内 LLM 的完整上下文来源。
- `DocCard` 是给开发者使用的显式外显记忆；需要时可以把其中内容复制给新的 chat，但不要求系统默认把整个工作区都喂给模型。
- `Session` 是一等对象，不再只是隐藏在页面底部的唯一终端。
- 多 `session` 的优先级高于完整终端历史；完整历史属于后续增强，而不是当前最小闭环。

## 当前实施切口

`2026-03-12` 起，v2 已进入第一刀实现，并已由你本人验证通过：

- 主页按 `ListWorkspace` 命名和收口，明确它是监控与筛选面；
- `CanvasWorkspace` 继续保留为关系观察面，而不是当前阶段的完整白板；
- `TaskCard` 开始拆分“人工推进状态”和“运行态”，避免继续把终端状态当成唯一任务状态。

当前下一步：

- `M8.1` 当前节点已由你本人验证通过：已支持最多 3 个 `Session`、任务绑定/复用和单观察窗切换；
- 下一步优先补一层轻量 `parsed events`，把等待态从纯关键词检测升级为“原始 PTY 数据 + 解析后状态事件”双通道；
- 在此基础上再推进 `M8.2 ListWorkspace` 的监控能力，而不是先回头补完整终端历史。
