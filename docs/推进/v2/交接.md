## 1. 当前未提交改动

当前工作区仍有未提交改动，切设备后优先关注这 4 个文件：

- `source/server/lib/session-output-parser.mjs`
- `source/server/lib/terminal-session-manager.mjs`
- `source/server/server.mjs`
- `source/web/app.js`

这些改动的目标是：

- 把 `waiting` / `resumed` 从内联启发式逻辑抽成轻量 `parsed events` 层；
- 通过 websocket 发送 `parsed_event` 给前端；
- 让任务卡在“绑定已有 Session”时，立即同步该 Session 的当前运行态；
- 拦住已关闭 Session 上的无效输入，减少错误日志噪音。

## 3. 下个设备优先测试

切设备后先不要扩功能，优先验证这 3 组内容。

### 3.1 parsed events

1. 运行 `npm run dev`
2. 打开 `http://127.0.0.1:3210`
3. 连接一个运行中的 `Session`
4. 输入 `Read-Host "Need input"` 回车
5. 确认：
   - 当前 `Session` 进入“等待处理”
   - 绑定任务进入“等待处理”
   - 状态日志出现“Session 进入等待态...”
6. 再输入任意内容回车
7. 确认：
   - `Session` 从等待态恢复
   - 任务从等待态恢复
   - 状态日志出现“Session 已恢复运行...”

### 3.2 绑定即时同步

1. 准备一个已经处于 `running` 或 `waiting` 的 `Session`
2. 找一个任务卡，在“绑定 Session”下拉框里切到这个 `Session`
3. 确认任务卡“运行态”立即同步变化

### 3.3 输入守卫

1. 选中一个已关闭的 `Session`
2. 点击连接后，在终端观察窗里随便输入几次
3. 确认“状态输出”面板里不要再刷：
   - `终端错误：Terminal session is not running.`

## 4. 状态日志入口

如果下个设备上要看应用层状态，不是看原始终端区，而是看首页的：

- 导航栏 `日志`
- 页面中的“状态输出”面板

这个面板主要记录：

- 连接 / 重连
- 任务绑定
- Session waiting / resumed
- 任务运行失败 / 终端错误

原始终端输出仍然看 `Session Terminal` 区。
