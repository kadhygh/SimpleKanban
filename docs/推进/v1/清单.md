# v1 清单

## 1. v1 目标

v1 目标是先完成一个本地优先的“可执行任务 + 网页终端”闭环，而不是完整看板/协作平台。

当前最小闭环：

1. 选择工程目录。
2. 创建或恢复网页终端会话。
3. 在网页中完成终端输入 / 输出交互。
4. 在终端中执行至少一种可配置执行器。
5. 页面刷新后恢复当前会话状态。
6. 通过 TaskCard 触发执行器运行，并把状态回流到卡片。
7. 维护任务依赖关系（仅结构展示），并在结构视图中查看子图。
8. 服务重启后，遗留 `running/waiting` 任务自动标记为 `lost`，避免“假运行”。

## 2. 当前默认技术方向

- M1 当前实现：零依赖 `Node.js` 本地服务 + 原生 HTML/CSS/JS 页面
- M2 当前落地方向：继续保留现有原生页面与本地 Node 服务，先渐进接入 `xterm.js`
- M2 当前后端方向：在现有本地服务上先接入 `WebSocket + node-pty`
- 后续演进方向：再视需要过渡到 `React + Vite + TypeScript`
- 模型核心：`Project + TerminalSession + ExecutorProfile + Task`

## 6. 当前实现说明

M1 当前已经完成的是“本地服务 + 当前项目选择 + 页面展示”这一层，并且已经由你本人完成手动确认。

M2 当前节点已完成并通过人工验证；后续继续沿用这套骨架推进 TaskCard 与结构层，优先目标仍不是切换技术栈。

为了先把链路跑通，当前代码采用：

- `source/server/server.mjs`：本地 HTTP 服务、API 与终端 WebSocket，包含 Task/依赖更新与运行入口
- `source/server/lib/project-store.mjs`：Project/Task 本地持久化 + M3 reconcile（`lost`）+（封存的）memory 结构
- `source/server/lib/terminal-session-manager.mjs`：单活跃终端会话管理（node-pty）
- `source/server/lib/executor-profiles.mjs`：执行器注册表、参数规范化与命令拼装
- `source/server/lib/folder-dialog.mjs`：Windows 文件夹选择对话框
- `source/web/index.html`：页面骨架
- `source/web/app.js`：前端交互逻辑（terminal / TaskCard / 依赖结构视图）
- `source/web/styles.css`：页面样式

当前进入 M2 时，优先采用“在现有代码上渐进接入”的策略：

- 前端继续保留原生 HTML/CSS/JS 页面；
- 后端继续保留当前本地 Node 服务；
- 在此基础上补齐终端会话、双向通信和状态展示；
- 待最小闭环稳定后，再决定是否切换到更完整的前端技术栈。
