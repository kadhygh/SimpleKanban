# TaskCard 执行闭环里程碑

日期：2026-03-09
状态：已由你本人验证通过

## 1. 里程碑结论

本节点完成的不是完整任务系统，也不是 canvas，而是先把 `Task` 从页面展示对象推进成真正可执行、可追踪、可回到终端的工作对象。

当前已完成并验证通过的最小闭环：

`TaskCard -> Run -> TerminalSession -> 状态回流到 TaskCard`

这意味着后续再扩展画布、连线、NoteCard 或结构层时，挂接的是实际执行闭环，而不只是视觉层。

## 2. 本节点完成内容

### 2.1 页面层

页面中新增了最小 `任务区`，支持：

- 创建 TaskCard
- 为 TaskCard 绑定执行器
- 从 TaskCard 直接点击运行
- 在 TaskCard 上看到当前状态
- 从 TaskCard 快速定位到终端区
- 同时查看多个任务的状态摘要

### 2.2 数据与接口层

在现有本地 JSON 持久化基础上，为任务补齐了最小数据结构与接口：

- 任务创建
- 任务读取
- 任务运行
- 任务状态更新
- 任务与当前终端会话的最小绑定

### 2.3 执行层复用

本节点没有重做执行层，而是直接复用了既有能力：

- `Project`
- `TerminalSession`
- `ExecutorProfile`
- 现有终端 websocket 链路
- 现有执行器注入能力

因此当前实现不是平行新造一套任务系统，而是把任务挂到已验证过的执行链路上。

## 3. 当前状态语义

TaskCard 目前支持以下最小状态：

- `未运行`
- `运行中`
- `等待处理`
- `已结束`

当前阶段状态回流已经可以承载：

- 运行启动后的执行中状态
- 终端需要人工继续时的等待状态
- 终端结束后的完成状态

## 4. 当前终端模型

当前阶段继续坚持：

- 单机
- 单项目
- 单活跃终端

因此当前不是“一张任务卡一个终端”，而是：

- 所有 TaskCard 共享同一个活跃终端
- 点击某张 TaskCard 的“运行”时，会复用当前终端
- 当前绑定任务会切换到该 TaskCard
- 点击“查看终端”时，是回到这个共享终端继续处理

这个语义已在页面文案中明确，避免误解成多终端模型。

## 5. 本节点解决的关键问题

在这个里程碑之前，执行器还是页面级工具；在这个里程碑之后，任务已经成为：

- 执行入口
- 状态承载对象
- 终端关联对象

这一步让后续的结构层建设有了真实落点。

当前阶段已经具备继续向结构层推进的基础，因为：

- Task 已经不是静态卡片
