# SimpleKanban Dashboard

最后更新：2026-03-11

## 1. 项目定位

SimpleKanban 是一个面向 Unity 本地开发流程的任务与执行管理器。

当前阶段不追求完整协作框架，而是优先打通：

- 本地项目绑定
- 网页终端会话
- CLI 交互与状态可见
- 可扩展执行器模型

## 3. 当前锁定决策

- v1 以 **网页托管终端** 为核心，而不是外部 terminal 窗口。
- v1 以 **单机 / 单项目 / 单活跃终端** 为最小目标。
- 依赖关系当前只做**结构展示**，暂不做运行约束（但实现上保留未来加 gating 的空间）。
- `memory` 功能暂时封存（默认禁用，未来有明确需求再启用）。
- 后续一个 `TaskCard` 可以关联多个可执行入口，因此底层先抽象 `ExecutorProfile`。
- `docs/rescource` 中的 `vibekanban` review 可作为参考，但不是必须照搬的实现依据。
- 当前 `M2` 继续采用渐进式实现：先在现有骨架上接入终端能力，再决定是否升级前端技术栈。

状态口径统一为：

- 已完成：你本人已实际验证通过；
- 进行中：功能开发中，或代码已实现但仍待你验证；
- 未开始：尚未进入实现。

补充约定：

- 只有你明确回复“验证通过”后，才继续推进下一步；
- 开发侧自测不能替代你的最终验收。

- “页面刷新维度的恢复”仍由 M2 链路承载（WS replay + session snapshot），与“服务重启可信性”分工不同。

## 6. 下一步

下一最小节点已收敛为：`M7 Canvas Spike`

目标：

1. 先把当前 Task 数据投影到一个轻量 canvas 区域；
2. 支持节点选中，并让选中态与现有任务区联动；
3. 用这个最小节点验证“未来主界面是否应该围绕 canvas 组织”，而不是先做纯表现重构。

当前明确不做：

- 不做完整无限白板编辑器；
- 不做复杂连线编辑；
- 不做产物层；
- 不恢复 memory。
